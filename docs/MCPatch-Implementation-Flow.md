> 目的：为在主分支（C# 重构版）重新实现 MCPatch 更新组件提供**语言无关**的实现蓝图。

## 1. 功能总览

启动页（PageLaunch）内嵌一个**不可删除**的更新卡片「MCPatch 更新」，目标用户是整合包服务器运营方：

- 从可配置的**更新源**读取版本列表，与本地当前版本比对，计算待更新版本链。
- 按顺序下载并应用**差量补丁包**，边改文件边推进版本号。
- 版本未更新时**阻止启动**，提示「版本不一致请更新」。
- 支持**版本隔离**（`.minecraft/` 与 `.minecraft/versions/<版本名>/` 两种布局）。
- 支持**多服务器源**（下拉框切换）。

### 非核心改动（用户确认**全部保留**）

1. 禁用软件本体自动更新（`ModSecret`：`UpdateStart` 直接返回；`LoadOnlineInfo` 跳过自动更新分支）。
2. 简化登录选项：新建档案时无条件显示「正版 / 第三方 / 离线」三种验证（不再按账号/网络情况隐藏）。
3. 移除 DEBUG / CI 环境下的「特殊版本提示」弹窗（`FormMain`）。

## 2. 核心概念与领域模型

| 概念 | 说明 |
|---|---|
| **更新源 Endpoint** | 一个服务器配置：`name`、`versionListUrl`、`packageUrlTemplate`。派生 `DisplayName` 用于下拉框展示。|
| **更新上下文 Context** | 一次检查/更新所需的全部输入：根路径、选中版本名、端点列表、选中端点下标。|
| **检查结果 CheckResult** | `当前版本 / 最新版本 / 全部版本 / 待更新版本链`，派生 `NeedUpdate`。|
| **进度 Progress** | 总进度（0~1）+ 当前补丁包进度（百分比 + 已下载/总字节）+ 消息文本。|
| **补丁包 PatchPackage** | 一个 zip（`<version>.mcpatch.zip`），内含 `.mcpatch-meta.json` 与若干数据条目。|
| **补丁元数据 Meta** | `new-folders / old-files / old-folders / new-files`。`new-files` 每项含 `mode/path/new-hash/bzipped-hash/raw-hash/raw-length`。|
| **版本状态文件** | 本地记录当前已应用版本：`mc-patch-version.txt`（存根路径下）。|

### 2.1 端点配置（`mcpatch.config.json`）

- 读取位置：优先 `<实例路径>/mcpatch.config.json`；若实例路径与根路径不同且根路径存在该文件，则用 `<根路径>/mcpatch.config.json`。
- 格式：**单对象**或**对象数组**均可；数组时 UI 提供服务器下拉框。
- 字段与默认值：

```json
{
  "name": "主服务器",
  "versionListUrl": "http://s13.yxsjmc.cn:20125/versions.txt",
  "packageUrlTemplate": "http://s13.yxsjmc.cn:20125/{version}.mcpatch.zip"
}
```

- 缺省字段回填默认值；`DisplayName` = `name`（非空）？否则为 URL 的 host(+path)，再否则「默认更新源」。
- 解析失败 / 无配置文件 → 回退为**一个默认端点**。
- 每一行版本号：按行切分，去 `\r`、去空行、去首尾空白、按序去重。

## 3. 检查更新（Check）

输入：`Context` + 进度/状态回调 + 取消令牌。输出：`CheckResult`。

1. **校验 Context**：非空、根路径非空、端点列表非空。
2. **取版本列表**（`GET versionListUrl`）：
   - 重试 3 次；状态回调：`首次获取中 → (重试中 x1..) → 已成功`；3 次仍失败 → `失败` 并抛出。
   - 两次重试间等待约 5s；可被取消。
3. **解析版本列表**：按行清洗 → `allVersions`（有序去重）。
4. **读当前版本**：从版本状态文件读取（见 6.1 版本隔离定位），空视为「未安装」。
5. **最新版本**：列表最后一项；空列表则空串。
6. **待更新链**：
   - 当前版本为空 → 待更新 = 全部版本。
   - 当前版本在列表中位置 `i`：`i` 为最后一项 → 无需更新；否则待更新 = `(i, end]` 子序列。
   - 当前版本不在列表中 → 视为全部待更新。
7. **NeedUpdate** = 待更新链非空。

---

## 4. 应用更新（Apply）

输入：`Context` + 有序待更新版本链 + 进度回调 + 取消令牌。对每个版本逐个执行；**每个版本应用成功即写入版本号**，降低大批量更新中途出错的影响。

总进度划分（`n` = 待更新版本数，`i` = 当前下标）：

```
版本阶段起点 = i / n
下载该包    = i/n + 0.85 * 包内进度 / n
下载完成    = i/n + 0.85 / n
应用完成    = (i+1) / n
```

### 4.1 每个版本的步骤

1. 构建包 URL：`packageUrlTemplate.replace("{version}", 版本号)`。
2. **下载**到临时文件（如 `mcpatch-<v>-<guid>.zip`）：
   - 流式写入，边读边上报字节进度；有 `Content-Length` 时上报百分比。
   - 重试 3 次；两次间等待约 5s；可取消。
3. **打开 zip，读取 `.mcpatch-meta.json`**（缺失或解析失败 → 报错）。
4. **删旧**：对 `old-files` 逐个删文件、对 `old-folders` 递归删目录。
5. **建新目录**：对 `new-folders` 逐个创建。
6. **写新文件**：对 `new-files` 中 `mode ∈ {f, m, fill, modify}`（有数据）的项：
   a. 在包内按 `path`（`\`→`/`，可去前导 `/`）定位数据条目；找不到 → 报错。
   b. 校验 `bzipped-hash`（存储字节的 SHA1，小写）。
   c. **解压**：原始数据是**无 BZ 头的 bzip2 流**，需补 `0x42 0x5A`（"BZ"）头后用 bzip2 解码。
   d. 解码时同时累加**原始长度**并计算**原始 SHA1**。
   e. 校验 `raw-length`（若 >0）、`raw-hash`（为空则用 `new-hash` 兜底）。
   f. **原子替换**：先写临时文件 `path.mcpatchtmp`，再用 `replace(temp, target, backup)`（目标已存在）或 `move(temp, target)`（不存在）；替换后清理 backup。
7. **推进版本号**：写 `mc-patch-version.txt`。
8. 清理下载临时文件。

### 4.2 版本隔离 / 路径定位（关键）

- 逻辑根目录为实例根路径（mods 等落盘位置），需把 meta 中的逻辑路径映射到真实路径：
  1. 统一 `\` 分隔、去前导 `\`。
  2. 若以 `.minecraft\versions\<选中版本名>\` 开头 → 去掉该前缀。
  3. 若以 `.minecraft\` 开头 → 去掉该前缀。
  4. 与根路径拼接得到真实路径。
- **防路径穿越**：拼接后的完整路径必须位于根路径之下，否则报「非法路径」。

## 5. 健壮性与错误处理

| 场景 | 策略 |
|---|---|
| 版本列表获取 | 重试 3 次，失败置「失败」状态并提供手动重试按钮 |
| 补丁包下载 | 重试 3 次 |
| 文件删除/写入 | 重试 6 次；处理只读属性、被占用（IOException/Unauthorized）；最终转成可读提示 |
| 目标文件被占用 | 提示「请先关闭正在运行的 Minecraft / Java / 文件预览」 |
| 取消 | 全链路携带取消令牌，检查点 `ThrowIfCancellationRequested` |
| 路径穿越 | 拒绝并报错 |
| 哈希/长度不匹配 | 抛出明确错误信息 |

## 6. 更新界面（UI）规格

位于启动页右侧的非删除卡片「MCPatch 更新」（默认 `Collapsed`），仅当前选中实例存在有效配置时显示。

### 6.1 布局

```
┌────────────────────────────────────────────┐
│ MCPatch 更新                     更新服务器 │ ← 右列下拉框（仅多源时）
│ 当前版本：xxx                              │
│ 最新版本：xxx（需要更新 / 已是最新）       │
│ 列表状态：首次获取中/重试中(x)/已获得/失败  │
│ [进度条 6px]                               │
│ 主进度文本                                 │
│ 包内进度文本（下载中：xx% 或 x/x 字节）     │
│ [立刻更新] [手动重试](仅失败时显示)         │
└────────────────────────────────────────────┘
```

### 6.2 行为

- **自动刷新**：页面加载后启动 2s 定时器轮询；以「根路径|版本名|端点」为实例键去重，键不变且非立即刷新则跳过；更新进行中跳过。
- **调度**：检查/更新在**后台线程**执行，结果与进度经 UI 线程回调；用实例键守卫，忽略过期回调。
- **服务器下拉**：端点列表发生变化（签名比较）时重建列表，尽量按 key 保持选中项；切换触发重新检查。
- **检查结果渲染**：展示当前/最新版本、`NeedUpdate` 标记；更新按钮仅 `NeedUpdate` 且未在更新中时可点；无需更新时进度条满。
- **更新流程**：
  - 点击「立刻更新」时若游戏正在运行/启动 → 拦截提示。
  - 校验存在待更新链；置正在更新标志，禁用按钮，进度清零，跑后台更新。
  - 进度回调驱动进度条 + 主/包进度文本。
  - 成功 → 完成提示；失败 → `IOException` 组给占用文件专属提示，其余给错误信息；日志记录；`finally` 恢复按钮、重新检查。
- **启动门禁**：面板可见时，若「正在刷新 / 正在更新 / 无结果 / 需要更新」→ 禁止启动。
- **启动按钮联动**：当被 MCPatch 门禁阻塞时，启动按钮置灰并文案改为「版本不一致请更新」；状态变化（含 MCPatch 状态切换后）必须刷新按钮。

## 附录 A：`.mcpatch-meta.json` 参考结构

```json
{
  "new-folders": [],
  "move-files": [],
  "change-logs": [""],
  "old-files": [".minecraft/mods/SomeOldMod-1.0.jar"],
  "old-folders": [],
  "new-files": [
    {
      "mode": "f",
      "path": ".minecraft/mods/SomeMod-1.4.0.jar",
      "old-hash": "",
      "new-hash": "...",
      "bzipped-hash": "...",
      "raw-hash": "...",
      "raw-length": 1018387
    }
  ]
}
```

> 说明：`move-files / change-logs` 当前实现未消费，但保留在协议中；`new-files` 数据条目是**无 BZ 头的 bzip2** 数据。
